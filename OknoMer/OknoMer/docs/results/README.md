# Контрольные результаты Android 0.4.0

На семи контрольных изображениях средняя абсолютная ошибка автоматического замера составила **48.7 мм по ширине** и **48.8 мм по высоте**. Контрольный внутренний проём имел размер 1200 × 1500 мм. Автопоиск выбрал наружный край рамы.

## Что проверено

Исходный код собран Gradle в отдельном клоне Git с JDK 17, Android SDK 35 и OpenCV 4.12.0. Созданы отладочный APK, APK инструментальных тестов и релизный APK. Тесты установлены на эмулятор Android 10. Основной сценарий включает расчёт, ручную правку, сохранение, открытие, переименование, удаление тестовой записи и экспорт. Между двумя фазами отдельная команда adb принудительно остановила приложение. Вторая фаза снова открыла объект, замер и его фотографию.

## Три ракурса одного контрольного проёма

Один искусственный проём имеет заданный размер 1200 × 1500 мм. На его модели есть внутренний край и наружная рама. Первые два расчёта в таблице используют одни и те же известные углы внутреннего края. Последний столбец получен при поиске обоих контуров по пикселям. Исходные изображения открываются по ссылкам.

| Ракурс | Заданный размер, мм | Линейный масштаб по А4, мм | С коррекцией по известным углам, мм | Полностью автоматически, мм |
|---|---:|---:|---:|---:|
| [Прямо](../../app/src/androidTest/assets/front.jpg) | 1200 × 1500 | 1200,0 × 1500,0 | 1200,0 × 1500,0 | 1246,5 × 1556,1 |
| [Небольшой наклон](../../app/src/androidTest/assets/angle_small.jpg) | 1200 × 1500 | 1055,9 × 1406,4 | 1200,0 × 1500,0 | 1256,7 × 1563,0 |

На сильном наклоне линейный расчёт занизил ширину на 270,1 мм и высоту на 183,3 мм. При известных углах гомография восстановила контрольную геометрию для всех трёх проекций. На фронтальном кадре автопоиск выбрал наружную границу рамы, добавив 46,5 мм к ширине и 56,1 мм к высоте относительно внутреннего проёма. Кнопка **Другой контур** переключает найденные границы.

## Маленькая карта и шум координат

Для небольшого эталона небольшое смещение его углов сильно влияет на гомографию, которую приходится продолжать на расстояние до проёма. В режиме карты 0.4.0 использует обратную последовательность. Сначала выпрямляется больший четырёхугольник проёма, затем стороны карты задают его физический масштаб.

Контрольный эксперимент повторяет каждую из четырёх сцен 100 раз. Ко всем координатам исходных углов добавляется независимый нормальный шум со стандартным отклонением 1 пиксель, начальное значение генератора 2026. На каждой попытке оба метода получают одни и те же точки. Старый подход в этом сравнении — гомография только по четырём углам карты с подстановкой её физических размеров. Новый — расчёт и проверки, реально применяемые в карточном режиме. Ошибка попытки равна большей из двух абсолютных относительных ошибок ширины и высоты.

| Сцена | Гомография по карте, допустимо из 100 | Медиана ошибки, % | Новый режим, принято из 100 | Медиана ошибки, % |
|---|---:|---:|---:|---:|
| Карта горизонтально | 83 | 43,958 | 100 | 2,610 |
| Карта вертикально | 62 | 45,713 | 95 | 2,375 |
| Карта повёрнута | 73 | 45,363 | 100 | 2,338 |
| Карта внутри контура | 70 | 37,749 | 100 | 2,703 |

Медианы и 95-е процентили вычислены по допустимым результатам каждого метода. Отказы приведены отдельно. Все 400 попыток моделируют ошибку разметки. Для оценки точности на телефоне нужны фотографии настоящих проёмов и независимые размеры по рулетке. Порядок проверки и подготовка итоговых таблиц приведены в [протоколе натурных испытаний](../field/README.md).

## Воспроизведение

На свежем эмуляторе выполните сборку и запуск тестов по [инструкции](../../README.md#проверки). Лог содержит размеры на известных углах, размеры при автопоиске, сравнение с простым масштабом и результаты эксперимента с шумом. Таблицы из полного лога можно получить командой:

```powershell
py -3 tools/control_report.py docs/results/android-check.txt docs/results
```
